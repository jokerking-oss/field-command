# 前线指令 · FIELD COMMAND

像素回合制战棋。浏览器游玩，支持 2–4 人联机自由混战和 2v2，空位由电脑接管，一个人也能开局。规则数值、指挥官与程序绘制的像素素材由本项目实现。

## 开始游戏

需要 Node.js 20 或更新版本，无需安装 npm 依赖。

- macOS：双击 `开始游戏.command`，浏览器会自动打开。
- Windows：双击 `开始游戏.bat`，按窗口中的本机地址打开浏览器。
- 终端：在项目目录运行 `npm start`，打开 **http://localhost:4173**。

页面的「建立作战」可设置 2–4 个席位、地图（47 张，可按人数过滤与搜索）、指挥官和对战模式。空位默认由电脑接管，一个人玩直接建 2 人局出击即可；朋友可随时加入。2v2 需要 4 个席位：赤焰 + 金叶一队，苍蓝 + 紫星一队。

## 局域网联机

1. 一台电脑启动服务；保持启动窗口运行。
2. 房主在浏览器中创建房间，在房间右侧复制邀请地址。
3. 朋友连接同一局域网，使用自己的浏览器打开这个地址，输入呼号后加入。
4. 新玩家会占用空位或电脑席位；房主可设置电脑补位，全部席位就绪后开始。

其他设备访问的是房主的局域网 IP（如 `http://192.168.x.x:4173`），而不是 localhost。启动窗口会列出检测到的地址；有多块网卡时，选择与朋友处于同一网段的地址。系统询问 Node 是否允许接收连接时，允许本地网络连接。若连不上，检查防火墙与路由器的访客隔离。

服务默认监听 `0.0.0.0:4173`。可通过 `PORT=其他端口 npm start` 改端口。

## 公网部署

服务本身就带公网模式，不需要改代码：

1. 把项目放到一台能长期运行的机器上，用 `npm start` 启动（平台注入的 `PORT` 会自动生效）。
2. 用反向代理 / 隧道把公网域名指到该端口，**注意放行 SSE 长连接**（`/api/rooms/.../events`，服务端每 20 秒发一次心跳）。
3. `data/` 目录需要可写；只读文件系统请用 `DATA_DIR=/可写路径 npm start` 指走。

**关于反向代理**：代理通常会在终止 TLS 之后改写 `Host`（服务因此看不到自己的公网域名），所以来源校验不能只比对 `Host`。默认策略是「能对上 `Host` / `X-Forwarded-Host` 就放行，否则要求浏览器自带 `Sec-Fetch-Site: same-origin`」。若你的代理不转发 `Sec-Fetch-*`，用 `ALLOWED_ORIGINS=https://你的域名` 显式声明公网主机名即可。

服务通过 `Host` 自动识别内网/公网：**公网模式下 `/api/rooms` 不再返回房间列表，也不会返回内网地址**——只有拿到房主给的那串房间码才能加入（否则任何人都能在大厅里挑房间坐进去）。想强制开关，用 `PUBLIC_MODE=1`（强制公网）/ `PUBLIC_MODE=0`（强制内网行为）。

公网模式下还会对建房（每 IP 每小时 12 次）和加入（每 IP 每分钟 30 次）限流，避免有人刷满 128 个房间把服务占死。

`data/*.json` 里含有各席位 64 位十六进制重连凭证，已在 `.gitignore` 中排除，**不要提交、也不要把 `data/` 挂成静态目录**。浏览器保持自己的席位凭证，刷新或断线后可恢复；大厅的「继续上次作战」也能返回。开局后不接受新玩家占用已有席位。玩家断线时，其回合等待重连，不会自动替玩家行动。提供服务的电脑退出时，对局暂停；重启服务后从存档恢复。首版不含自动迁移房主、公开匹配、旁观模式或跨设备找回席位。

## 怎么玩

- 点击己方单位，查看青色移动范围；点击目的地后选择待机、占领、补给或兵种特殊指令，或点击红色敌军预览并确认攻击。
- 移动与命令一起提交，在确认前可随时取消。Esc 取消预选，Space 打开结束回合确认。
- 步兵、机动步兵可以占领城市、工厂、机场、港口与总部。占领速度取决于血量，离开据点会失去未完成的占领进度。
- 点击空闲的己方工厂、机场或港口，分别生产陆军、空军或海军。新部队下一个己方回合可行动。
- 运输直升机与登陆舰可装载、卸载部队；潜艇可下潜或上浮；维修艇可修理相邻舰船；爆破无人机攻击后会自毁。
- 据点产生收入，并对驻扎的己方部队维修、补给。维修需要资金。
- 间接火力不能在移动后攻击，且有最小射程。近战单位在射程、弹药与目标类型允许时反击；下潜潜艇只有反潜单位能攻击。
- 战斗积累指挥能量：50 点发动普通能力，100 点发动超级能力。
- 夺取总部使其所属玩家出局；没有单位且没有工厂的玩家出局；最后的队伍获胜。2v2 队友独立管理资金与部队。

## 当前内容

- 25 种单位：13 种陆军、6 种空军、6 种海军，含防空车、轨道炮车、截击机、运输直升机、潜艇与航空母舰。补给车负责补给；运输由运输直升机和登陆舰承担。
- 47 张地图：原有 3 张战场与新增 44 张原创地图。创建房间时可按名称和人数筛选；部分海岛地图需要海空运输配合。
- 2 名原创指挥官：林岚（突击先锋）、周衡（战地工程师），各有普通和超级能力。
- 地形移动成本与防御、兵种克制、弹药燃料、占领、生产、维修、补给、AI、对局结果。
- 程序绘制原创像素地形与兵种，逐格移动、转向、双军交火、击毁与倒下特效，以及可开关的合成提示音。
- 占领动画直接显示在总地图上：中立据点分两次升旗；占领敌方据点时先把原旗降到半杆，下次降尽原旗并升起己方旗。AI 会等待一条行动的动画结束后再执行下一条。
- 桌面与触屏布局。

全图可见；战争迷雾、完整战役和地图编辑器尚未实现。

## 存档

服务端在每次已确认的行动、房间设置改变后保存 `data/autosave.json`，通过临时文件写入、fsync 与原子替换落盘。上一个有效版本保留为 `.bak`，启动时主存档损坏可回退备份。存档含 schema 版本，读取时验证房间与战局状态。

「保存对局」创建单独的 `data/manual-房间码.json` 快照，不会被自动存档覆盖。正常继续游戏使用最新自动存档；手动快照供备份保存，本版没有回滚菜单。服务端存档包含重连凭证，静态服务不会暴露 data 目录。清除浏览器站点数据会丢失本机席位凭证。

## 项目结构与验证

- `public/shared/engine.mjs`：共享纯规则引擎与 AI；`map-data.mjs`、`combat-data.mjs` 分别保存地图与兵种克制数据。
- `public/renderer.mjs`：原创 Canvas 像素绘制与交互坐标。
- `public/property-flag.mjs`：地图据点的升降旗状态与时序。
- `public/app.mjs` / `style.css` / `index.html`：房间与战场界面。
- `server.mjs`：Node HTTP + SSE，服务端验证指令，按房间广播状态。
- `save-store.mjs`：版本化原子持久化与备份。
- `test/`：规则、AI、存档与真实 HTTP 多客户端集成测试。

运行 `npm test`。测试使用临时端口和临时存档，不会更改正式 data 目录。
